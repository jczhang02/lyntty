## Decisions captured

- Stable personal use is the initial target, not public SaaS release.
- Public GitHub target is `jczhang02/lyntty`.
- Public push requires full git-history secret scan first.
- Production relay URL is `https://relay.jczhang.cc`.
- Cloudflare `relay` record starts DNS-only.
- Relay deploy target is single VPS with Docker Compose, host Caddy HTTPS, PGlite under `/opt/lyntty/data`, restart `unless-stopped`, and daily encrypted local backup.
- Relay image comes from GHCR as `ghcr.io/jczhang02/lyntty-relay:<tag>`; production deploy pins `sha-<shortsha>`.
- VPS deploy is manual GitHub Action over SSH; VPS does not git pull or build source.
- `HANDY_MASTER_SECRET` stays on VPS and in password manager/encrypted backup, not GitHub Secrets.
- Production Android package id is `dev.jczhang.lyntty`; dev/E2E package id is `dev.jczhang.lyntty.dev`.
- Production/dev app data are isolated by package id.
- Permanent release keystore is `lyntty-release.jks`, never committed, backed up encrypted, and injected to CI from GitHub Secrets.
- APK release workflow is manual `workflow_dispatch` only.
- GitHub Releases is APK distribution source; relay `/v1/version` returns manifest data.
- Android version comparison uses `versionCode`; GitHub Release tag format is `android-v<versionName>-<versionCode>`.
- `latest.json` is generated by CI, not hand-edited.
- APK self-update uses Expo/React Native APIs to download, verify `sha256`, and invoke Android Package Installer with user confirmation.
- `REQUEST_INSTALL_PACKAGES` is allowed for production APK.
- No native Android updater shim and no silent install.
- EAS Update is secondary JS/assets OTA only, not main native update path.
