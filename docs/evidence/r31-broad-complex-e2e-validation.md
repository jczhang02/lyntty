## Fixes from E2E

### Stable pairing automation IDs

File: `packages/lyntty-app/sources/app/(app)/terminal/index.tsx`

- Added `testID="lyntty-pair-accept"` to the native `Pair Node` accept button.
- Added `testID="lyntty-pair-reject"` to the native reject button.

Reason: the active native Pair Node route was `terminal/index.tsx`, while only `terminal/connect.tsx` had testIDs. Maestro text taps could hit the wrong control or fail to find the button reliably.

### Android dev-client deep-link fallback

File: `scripts/e2e/run-maestro.sh`

- Special-cases `02_pair_node.yml` on Android when `LYNTTY_MAESTRO_DEVICE` and `LYNTTY_MAESTRO_PAIRING_URL` are set.
- Runs a Maestro prep flow to launch/select the dev server.
- Delivers `lyntty://terminal?...` through `adb shell am start -a android.intent.action.VIEW -c android.intent.category.BROWSABLE`.
- Runs a second Maestro accept flow using the stable `lyntty-pair-accept` selector.

Reason: Maestro `openLink` logged success but often left the app on Sessions Home in the Expo Dev Client. Direct adb delivery opened the Pair Node screen; `BROWSABLE` improved reliability.
