# R64 7u7 duplicate assistant reply + a9k LXGW font

Date: 2026-07-07

## Scope

Beads:

- `lyntty-7u7` — duplicate assistant text from live Pi extension plus JSONL fallback.
- `lyntty-a9k` — embed LXGW font in the mobile app.

Safety:

- No live global Pi extension install/reload.
- No live `lynttyd` or current Pi/tmux pane testing.
- CLI checks used temporary `HOME`, `LYNTTY_HOME_DIR`, and `PI_AGENT_DIR`.
- Android validation used a local release-style APK build only; no physical phone run.

## 7u7 root cause

Workflow/root-cause review found the source path was `lynttyd` Pi extension delivery bookkeeping:

1. Pi extension live `message_update` text is buffered by `PiSessionProtocolMapper`.
2. `flushPendingLiveText()` sends flushed assistant text to the relay before `agent_end`.
3. That flush marked current JSONL entries delivered without assistant-message inclusion.
4. Exact assistant text fallback marking was deferred until `agent_end`.
5. If JSONL fallback observed the same assistant message between live flush and final marking, it imported the already-rendered text again.

Code review also found a preservation risk: the exact assistant-text ledger used only lower cutoff + 5 minute TTL. A later intentional assistant reply with the same text could be suppressed if fallback had to recover it.

## 7u7 fix

- Extracted Pi extension delivery helpers in `packages/lyntty-cli/src/daemon/run.ts` for direct regression coverage.
- `flushPendingPiLiveText()` now appends delivered non-thinking assistant text and immediately calls exact-text assistant delivery marking after relay flush.
- Non-`agent_end` live assistant text envelopes now mark exact assistant text immediately when delivered text changes.
- `PiExternalMirror` assistant delivered-text entries now have an optional upper bound.
- `agent_end` caps the delivered assistant-text window at `eventTime + 30s`; next `agent_start` caps any still-open window at the new turn boundary.
- Added regressions proving:
  - live flush marks assistant text immediately;
  - matching assistant JSONL fallback is dropped;
  - different/later intentional same-text assistant fallback is preserved after the delivered turn window.

## a9k font decision

- Font: LXGW WenKai Regular, upstream `lxgw/LxgwWenKai` `v1.521`, OFL-1.1.
- Full upstream TTF is about 25 MiB, so the app embeds a subset instead of the full font.
- Embedded files:
  - `packages/lyntty-app/sources/assets/fonts/LXGWWenKai-Regular-Subset.ttf` — 549,252 bytes.
  - `packages/lyntty-app/sources/assets/fonts/LICENSE-LXGWWenKai-OFL.txt`.
- Subset includes app Chinese strings, product terms, Latin/basic punctuation, CJK punctuation, and fullwidth forms. Missing glyphs fall back through platform font fallback.
- `Typography.body()` now uses `LXGWWenKai-Regular`; compact UI sans and code mono remain unchanged.
- Font loading was added to both native and Tauri fallback `Fonts.loadAsync()` maps in `packages/lyntty-app/sources/app/_layout.tsx`.

## Review

Read-only reviewer checked the diff and found one high-risk issue: unbounded exact assistant text dedupe could suppress intentional repeated assistant replies within the 5 minute ledger TTL. That issue was fixed by adding assistant delivery upper bounds and turn-boundary caps, then re-running the focused CLI suite.

Manual review after the fix checked:

- live assistant flush path marks exact text only after relay flush;
- assistant JSONL fallback dedupe is exact text + bounded turn window;
- different/later fallback text remains recoverable;
- LXGW asset size stays below 1 MiB instead of adding the full upstream 25 MiB font;
- OFL license is bundled;
- APK contains the exact subset font hash.

## Not run / limitations

- Physical-phone validation was not run.
- Maestro `03_history_send_reply.yml` and `04_reconnect_smoke.yml` were not run because this isolated validation only created a fresh account and paired node; it did not create an isolated Pi history session row for `${HISTORY_TITLE}`.
- Visual font rendering on physical Android hardware was not run; emulator Maestro validated APK launch/account/pairing paths.
- No live global Pi extension install/reload or current session mutation was performed.

## Residual risk

- Exact text dedupe deliberately prefers preserving fallback recovery over broad duplicate suppression. If live and JSONL text differ, both remain visible.
- If Pi extension live events stop before both `agent_end` and the next `agent_start`, an open exact-text delivery mark can persist until TTL expiry; normal completed turns are capped at `agent_end + 30s`.
- LXGW subset covers app/product Chinese terms and common punctuation, not all possible Chinese session content; missing glyphs rely on platform fallback.
- APK build plus Maestro proves emulator launch/account/pairing. Physical-device typography rendering remains unverified.
